feat(registry,bridge): path-boundary enforcement on done()

Round 2 of the Multica bridge roadmap (see examples/multica_bridge/README.md).

- Add ``mac.protocol.errors.BoundaryViolationError`` carrying the list of
  violating path patterns. Distinct from the existing soft
  ``boundary_review=block`` annotation stored on a HandoffResult: this is
  the hard-refusal counterpart.
- Add ``Registry.enforce_path_boundaries(task_id, handoff)`` that returns
  the passing files when the agent's ``allowed_paths`` / ``forbidden_paths``
  are honoured and raises ``BoundaryViolationError`` otherwise. Empty
  ``allowed_paths`` AND empty ``forbidden_paths`` is permissive (backward
  compatible with agents that opt out of boundary enforcement).
- Add opt-in ``enforce_boundaries: bool = False`` parameter to
  ``Registry.done()`` that calls the new method before saving the handoff.
  Violations short-circuit with a structured
  ``{"status": "boundary_violation", "violations": [...]}`` result so the
  caller can show them without losing the task state.
- Wire the bridge ``_on_agent_completed`` handler to pass
  ``enforce_boundaries=True``. On a refused handoff the webhook still
  returns 200 (consistent with the existing reverse-channel safety net) and
  the reverse channel is skipped -- no review packet is posted because no
  handoff was persisted.
- Update ``examples/multica_bridge/README.md``: move "Path boundary
  enforcement" out of "Next steps" into "What this PoC does now"; rewrite
  the remaining next-steps list around severity upgrades, conflict-aware
  routing, and agent-card sync from Multica.
- Tests:
  * ``tests/test_path_boundaries.py`` (new, 9 tests): covers the registry
    method, the ``done()`` opt-in flag, idempotent registration, and the
    refusal behaviour under both allowed/forbidden patterns.
  * ``tests/test_multica_bridge_reverse_channel.py``: add an end-to-end
    "boundary_violation -> structured 200, no reverse channel, no
    HandoffResult persisted" test. Also adds an ``isolated_bridge`` /
    ``isolated_client`` fixture pair so per-test runs do not pollute the
    shared ``mac.db`` (resolves a latent flake in the conflict-overlap
    test where stale state from previous runs leaked through).
- All 322 tests pass, 1 skipped.

Tested locally; no live Multica instance required for unit tests.
